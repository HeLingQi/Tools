# Goal：本地无人值守目标扩展

基于 `pi-mono-goal@0.2.0` 修改，保留原作者 MIT 许可（见 `LICENCE.md`）。
本地目录：`~/.pi/agent/extensions/goal/`。Pi 自动发现 `index.ts`，不需要安装 npm 包或新增依赖。
使用当前 Pi 的 `agent_before_settle` 边界接口（已在本机 Pi 1.3.0 验证）。

## 使用

修改后先在 Pi 执行 `/reload`，或重新启动 Pi。

```text
/goal 实现需求，并运行测试验证
/goal auto on
```

`auto on` 会立即开始执行（忙碌时则在当前运行结束后继续）。模型每完成一个阶段，会在目标未完成且没有停止条件时自动进入下一阶段。

```text
/goal show                 查看目标、进度及停止原因
/goal pause                暂停目标并中止当前执行
/goal resume               恢复目标；auto 模式下立即继续
/goal auto off             关闭自动续跑，保留目标引导
/goal edit 新目标文本      修改目标描述
/goal update 当前进度      手动更新进度
/goal done 已完成并验证    标记完成
/goal block 缺少凭据       标记阻塞
/goal clear                取消目标
```

`/goal mode manual|assist|auto`：

- `manual`：只持久化和显示目标。
- `assist`：每次模型请求携带最新目标和进度，不自动续跑。创建目标时默认此模式。
- `auto`：在 assist 基础上无人值守续跑，必须明确开启。

## 停止条件与边界

- 目标标记为 `completed`、`cancelled`、`blocked` 或 `paused`。
- 用户中止当前运行，或 Pi 的重试/恢复流程结束后仍执行失败：暂停，需 `/goal resume`。
- 模型要求用户输入或确认：阻塞，不代替用户批准。
- 连续两次自动续跑没有新的进度摘要或计划变化：暂停。重复相同内容、只改下一步、在相同摘要上附带说明或调用工具不算新的进度。
- 用户消息或其他续跑已排队：交还 Pi 处理，不额外排入重复任务。

**无轮数、工具次数、Token、费用或时长预算，也不再单独记录目标用量。** Pi 自身的用量统计不受影响。

停滞检测依赖模型报告的进度，只在阶段结束时判断，不是客观完成度验证；它不能阻止单次运行内无限调用工具或长期不返回的外部操作。移除预算意味着费用和运行时间没有扩展级上限。

这不是后台常驻服务：需要 Pi 进程保持运行。重载、恢复会话或切换分支只恢复状态，不自动启动任务；查看目标后使用 `/goal resume` 或 `/goal auto on` 继续。已完成或已取消的目标不能直接 resume，需创建新目标。

## 模型工具

- `get_goal`：读取目标和进度，可选择查看历史。
- `create_goal`：创建目标，支持 `mode` 和显式 `replace`。
- `update_goal`：更新摘要、计划、下一步、阻塞原因、模式和状态。未提供 `summary` 时，`progressNote` 作为摘要使用。

阻塞不再视为结束，不能在未指定 `replace` 时被新目标静默替代。完成或阻塞后仍允许模型给用户最终说明。

## 持久化与旧版本兼容

继续使用 Pi 会话中的 `goal-event` 自定义事件，从当前分支恢复，不创建额外数据库或目标文件。
旧版目标、进度和状态可直接读取；旧预算和记账字段被忽略，不改写原始会话文件。
上下文只替换扩展自有的隐藏消息，不删除用户输入或源码中恰好包含目标标记的内容。

必须停用 `settings.json` 中的 `npm:pi-mono-goal`，避免与本地版重复注册命令和工具。

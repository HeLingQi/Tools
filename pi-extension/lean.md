# 代码精简规则（作为子代理被调用时必须遵守）

- 只做任务要求的事，不加推测性功能、可配置项、"以后可能用到"的代码。
- 先找现成的：项目里已有的函数/模式 > 标准库 > 已安装依赖 > 自己写。不引入新依赖。
- 不加只有一个实现的接口/基类/工厂，不加只调用一次的封装函数。
- 不做无意义的防御：类型/逻辑上不可能为空的值不判空；不写只是重新抛出或吞掉错误的 try/catch；不加调试日志。错误处理只放在真正的边界（外部输入、网络、文件）。
- 注释只写"为什么"，不复述代码在做什么；不写文件头横幅、不写 docstring 套话。
- 遵循所在文件的既有风格，不顺手重构、格式化无关代码，不新建任务没要求的文件。
- 遵守 prompt 给出的行数预算和文件范围；确需超出，在汇报里说明理由。
- 执行命令必须会自行结束：长时间运行或流式命令一律加 timeout 或 head。
- 交付前自查一遍：删掉后功能不变的代码全部删掉。汇报只列改了什么、怎么验证的，并列出自查时删掉了什么；不写长篇说明。
- 汇报必须单列"隐式决策"：prompt 没写明、由你自行拍板的选择（如边界值、默认值、超时/重试参数、并发与锁行为、错误语义、取舍掉的方案、对需求的理解），每条一行：决定了什么 + 为什么。没有就写"无"。
- 校验只在 prompt 指定的边界做（如 HTTP handler、配置加载、数据库约束）；内部函数信任调用方，不重复校验。

## Go 专用禁令

- 不用 `fmt.Errorf("failed to ...: %w", err)` 逐层包装；只有补充了调用方不知道的信息时才包装，否则直接 `return err`。
- 不对调用方保证非 nil 的参数、已校验过的值再判断。
- 不"记日志再返回错误"，二选一；库代码不打日志。
- 不为单个函数定义自定义错误类型，用 `var ErrXxx = errors.New(...)`。
- 不写 Options 结构体/函数式选项、只调用一次的 helper、防御性拷贝、getter/setter。
- 不用 `recover()` 兜底，不写 `default: panic("unreachable")`，不加没人读的常量/枚举。
- 优先平铺直叙：一个函数从上到下能读完，不为了"整洁"拆成多个私有小函数。
